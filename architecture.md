# Архитектура тренажёра ЕГЭ (задание 24)

## Стек

- **HTML5** — разметка страниц.
- **CSS3** — оформление.
- **ES6+** — клиентская логика без сборщиков и без Node.js.
- **Pyodide** (CDN) — только для этапов 4 и 5 (выполнение Python в браузере).
- **CodeMirror 5** — редактор кода.
- **SortableJS** — только для этапа 3 (перестановка фрагментов).

Все библиотеки подключаются с CDN. Серверной части нет: статический сайт.

## Структура папок

```
/
├── architecture.md
├── content-plan.md
├── favicon.svg
├── css/          # style.css — главная, stage.css — этапы
├── js/
│   ├── storage.js         # единственный владелец localStorage
│   ├── shared.js          # общие утилиты (экранирование, перемешивание, загрузка JSON)
│   ├── app.js             # главная страница, прогресс, диагностика
│   ├── pyodide-runner.js  # запуск Python в браузере
│   └── stage0.js … stage5.js
├── data/         # контент заданий (JSON)
├── files/        # вспомогательные файлы (примеры, вложения)
└── tests/        # проверки целостности, запускаются через node
```

Порядок подключения скриптов на странице этапа фиксирован:
`storage.js` → `app.js` → `shared.js` → `stageN.js`.

## Данные и прогресс

- Весь учебный контент (задания, тексты, варианты ответов, эталоны) хранится в JSON-файлах в каталоге `data/`.
- Прогресс пользователя сохраняется в `localStorage` под ключом `ege24_trainer_progress`
  (схема версии 2: `stages`, `answers`, `results`, `sessions`, `drafts`, `reflection`).
  Старый формат `{"0":true}` читается и мигрирует автоматически.
- Доступ к хранилищу идёт только через `js/storage.js` (`window.Store`). Если
  `localStorage` недоступен — состояние живёт в памяти до перезагрузки.
- Прямой заход на закрытый этап перехватывается `Store.requireStage(N)`.
