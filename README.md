# Интерактивный тренажёр по информатике: задание № 24 ЕГЭ

Статическое веб-приложение для подготовки к заданию № 24 ЕГЭ по информатике
(обработка символьной информации). Проект выполнен в рамках дисциплины
«Педагогический дизайн».

---

## 1. О проекте (Аннотация)

**Тренажёр** — это интерактивная образовательная среда, которая последовательно
формирует у школьника навык **самостоятельного написания и отладки программ** для
обработки символьной информации.

**Целевая аудитория:** учащиеся 10–11 классов, готовящиеся к ЕГЭ по информатике.

**Какую проблему решает.** Задание № 24 требует не столько знания теории, сколько
устойчивого алгоритмического навыка: прочитать условие, вспомнить конструкцию
(цикл, срез, работу с файлом), написать код и — главное — найти ошибку, если
ответ не совпал с ожидаемым. Обычные сборники задач дают только «задача + ответ»,
из-за чего ученик заучивает решения вместо того, чтобы понимать логику.

Тренажёр закрывает этот разрыв: он ведёт ученика по цепочке навыков — от
узнавания знаков кода до полноценного экзаменационного формата с двумя тестами
(малым и большим файлом) и блоком рефлексии. Мгновенная обратная связь и система
подсказок заменяют учителя там, где нужна немедленная реакция на действие ученика.

## 2. Технологический стек и архитектура

### Технологии

| Технология | Роль в проекте |
|---|---|
| **HTML5** | семантическая разметка страниц |
| **CSS3** | оформление, сетки, состояния (подсветка верно/неверно) |
| **Vanilla JS (ES6+)** | вся логика: прогресс, проверка ответов, анимации, отладка |
| **Python + Pyodide (WebAssembly)** | запуск Python непосредственно в браузере |
| **CodeMirror 5** | редактор кода с подсветкой синтаксиса (этапы 4–5) |
| **SortableJS** | drag-and-drop для сборки программы из блоков (этап 3) |

**Проект полностью статический:** у него нет бэкенда, базы данных и сборщика
(webpack/vite/Node.js не используются). Все зависимости подключаются по CDN, JS
написан без ES-модулей — это сделано намеренно, чтобы проект работал как есть и
легко разворачивался на **GitHub Pages**.

### Архитектура папок

```
.
├── index.html            # главная: список этапов и прогресс
├── stage0.html … stage5.html   # страницы этапов (0–5)
├── css/
│   ├── style.css         # общие стили, главная страница, баннер Dev Mode
│   └── stage.css         # стили страниц этапов (тесты, редактор, анимация)
├── js/
│   ├── app.js            # прогресс (localStorage), доступность этапов, сброс
│   ├── pyodide-runner.js # общий модуль запуска Python в браузере
│   └── stage0.js … stage5.js   # логика каждого этапа
├── data/                 # банки заданий (JSON)
│   ├── stage0.json       # этап 0: модули «Обозначений»
│   ├── placement.json    # тест на пропуск этапа 0
│   ├── stage1.json       # этап 1: вопросы по синтаксису
│   ├── stage2.json       # этап 2: сценарии анимаций
│   ├── blocks.json       # этап 3: задачи-сборки из блоков
│   ├── stage4.json       # этап 4: задачи с ошибками в коде
│   ├── hints.json        # трёхуровневые подсказки (этап 4)
│   └── tasks.json        # этап 5: условия и эталонные ответы
└── files/                # тестовые файлы для этапа 5 (малый и большой)
```

### Почему данные вынесены в JSON (data-driven)

Весь учебный контент — вопросы, задачи, варианты ответов, сценарии анимаций,
подсказки — хранится в отдельных **JSON-файлах**, а не внутри JS. Это реализует
принцип **data-driven design**:

- **учитель может добавлять и менять контент без правки кода** — достаточно
  отредактировать JSON;
- логика (`.js`) отделена от содержания (`.json`), поэтому код не ломается при
  изменении банка заданий;
- один и тот же движок обслуживает все задачи этапа: новая задача не требует
  нового кода, если она следует той же структуре.

## 3. Педагогический дизайн и методика

### Идея: снизить когнитивную нагрузку, разложив навык на 6 этапов

Задание № 24 — сложный составной навык. Если сразу предложить ученику написать
программу с нуля, он столкнётся с перегрузкой: нужно одновременно помнить
синтаксис, логику алгоритма, работу с файлами и уметь отлаживать. Поэтому навык
**декомпозирован на этапы 0–5**, каждый из которых формирует отдельную
составляющую — от простого узнавания к самостоятельной продуктивной
деятельности (принцип «от репродукции к творчеству», опора на таксономию Блума).

### Этап 0 — «Обозначения»

Пять модулей (структура кода, ключевые слова, функции и методы, спецсимволы и
т.д.), внутри которых задания идут по одному и каждый следующий модуль
открывается после прохождения предыдущего (не менее 80%). Формирует **узнавание
знаков и ключевых слов** Python.

Для сильных учеников предусмотрен режим **Placement Test** («Я знаю базу»):
10 смешанных вопросов из всех модулей; при результате **≥ 90%** этап сразу
засчитывается и открывается этап 1, при меньшем — ученик возвращается к обычному
прохождению модулей. Это позволяет не тратить время сильного ученика на
повторение и одновременно диагностировать пробелы у остальных.

### Этап 1 — «Синтаксис»

Вопросы «что делает эта строка кода?». Формирует **умение читать логику кода**,
а не писать его. Каждое прохождение собирается случайной выборкой из банка
вопросов, поэтому один и тот же тест не повторяется.

### Этап 2 — «Анимация»

Пошаговое выполнение программы: **подсветка текущей строки**, **таблица значений
переменных** на каждом шаге и текстовое пояснение. Формирует **понимание
динамики выполнения алгоритма** — ученик видит, как меняется состояние программы
от строки к строке, что напрямую связано с ручной трассировкой на экзамене.

### Этап 3 — «Сборщик»

Сборка программы из блоков кода с помощью drag-and-drop. Формирует **структурную
декомпозицию**: понимание порядка операторов и вложенности. В наборы блоков
намеренно добавлены «блоки-ловушки» (дистракторы), чтобы исключить сборку
наугад.

### Этап 4 — «Отладчик»

Дан код с ошибкой, нужно её найти и исправить, проверяя себя запуском Python
(через Pyodide). Формирует **алгоритм поиска ошибок**: *запустил → увидел
расхождение с ожидаемым → нашёл причину → исправил → перепроверил*. Это
центральный навык для задания № 24.

### Этап 5 — «Самостоятельное написание»

Полная **имитация экзаменационного формата**: ученик пишет программу с нуля, а
система проверяет её на **малом и большом файле** (большой файл защищает от
решений «на глазок» и подсказывает, что нужен эффективный алгоритм). После
успешной проверки — блок **рефлексии**.

### Прогресс

Прохождение этапов сохраняется в `localStorage` (ключ `ege24_trainer_progress`).
Следующий этап открывается после предыдущего; порог прохождения этапа — 80%
правильных ответов.

## 4. Методические тонкости реализации

- **Мгновенная педагогическая обратная связь.** Вместо сухого «Неверно»
  используется поле `pedagogical_hint` — **наводящий вопрос**, который помогает
  ученику самому прийти к правильному ответу. Ошибка — это материал для разбора,
  а не повод снизить мотивацию.

- **Трёхуровневая система подсказок (этап 4).** Подсказки выдаются
  последовательно: от общего направления («где искать причину») к указанию на
  конкретную строку — но **без готового ответа**. Порядок «сначала попробуй сам,
  потом подсказка» закрепляет самостоятельность.

- **Вариативность (пулы заданий).** Каждое прохождение этапа формируется
  **случайной выборкой** из банка заданий (JSON): на этапе 1 — по 2 вопроса из
  каждой темы, на этапах 2–5 — случайная задача. Это исключает механическое
  заучивание ответов и заставляет каждый раз решать задачу заново.

- **Разделение оценки и диагностики.** Система фиксирует не только итоговый
  балл, но и то, **какие именно** шаги вызвали затруднение (неверные ответы,
  сработавшие подсказки). Это даёт учителю материал для разбора ошибок.

## 5. Как запустить локально

Проект статический, но страницы загружают данные через `fetch()`. Браузер
**блокирует** запросы к локальным JSON-файлам из соображений безопасности при
открытии через `file://`, поэтому нужен **локальный веб-сервер**.

**Самый простой способ для преподавателя (Python):**

```bash
# из папки проекта
python -m http.server 8000
```

Затем откройте в браузере: <http://localhost:8000/index.html>

**Альтернативы:**

- расширение **Live Server** для VS Code — открыть `index.html` и нажать
  «Go Live»;
- любой другой статический сервер, например `npx serve`.

**Важно:**

- этапы 4 и 5 используют Pyodide — при первом открытии идёт загрузка
  WASM-рантайма Python (до готовности показывается «Загрузка Python…»);
- для работы этапов 4–5 и этапа 3 требуется **подключение к интернету**
  (CDN-библиотеки Pyodide, CodeMirror, SortableJS);
- режим разработчика (все этапы разблокированы) включается параметром в адресе:
  <http://localhost:8000/index.html?dev=true>
